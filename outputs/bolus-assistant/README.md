# Bolus Assistant

Русскоязычный дневник диабета. Основная версия — **нативное local-first приложение для iPhone** ([ios/](ios/README.md)): SwiftUI + SwiftData, все данные на устройстве, работает в Airplane Mode и не требует сервера, Docker, аккаунта или адреса сервера. Интернет нужен только для поиска во внешних каталогах еды и для необязательного AI. Архитектура, офлайн-матрица, резервные копии и перенос данных с сервера: [docs/LOCAL_FIRST.md](docs/LOCAL_FIRST.md).

Веб-версия на Next.js / FastAPI (описана ниже) сохранена: backend служит эталонной реализацией (reference) расчётов, с которой iOS-ядро сверяется общими тестовыми векторами. Личная версия с общей формой записей, учётом шага устройства, импортом тренировок Apple «Здоровье» и подключением OpenAI / Tokenn.

В текущей локальной установке расчёт включён по запросу владельца для личного использования (`CLINICAL_USE_ENABLED=true`); владелец сообщил о проведённой клинической валидации. Этот статус не является результатом независимой проверки разработчиком. Техническая модель IOB и правила расчёта описаны в `docs/ALGORITHMS.md`. Автоматический демо-вход отключён, личные аккаунты начинают с пустого дневника.

## Запуск через Docker Compose

Docker Compose нужен только для веб-версии. Приложению для iPhone (**[ios/Bolus.xcodeproj](ios/Bolus.xcodeproj)**) сервер не нужен: [установка через Xcode](ios/README.md), для установки на устройство нужна ваша Apple Team. Веб-сервер запускается следующими командами.

```sh
cp .env.example .env
# Замените POSTGRES_PASSWORD на длинное случайное значение (буквы/цифры/-/_).
# Настройте CLINICAL_USE_ENABLED для своей установки.
docker compose up -d --build
```

Открыть **http://localhost:8080**. Все 6 сервисов запускаются: `frontend`, `backend`, `postgres`, `redis`, `worker`, `nginx`. PostgreSQL, Redis и backend не публикуют порты наружу. Nginx по умолчанию доступен только на loopback хоста. На первом экране создайте личный аккаунт или войдите. Далее подтвердите параметры терапии. Исходный `.env.example` оставляет расчёт отключённым, демо отключено во всех обычных запусках.

```sh
docker compose ps
docker compose logs --tail=40 backend worker
docker compose down                 # сохраняет данные в volumes
```

Не используйте `down -v`, если нужно сохранить дневник. Для development с автоперезапуском backend:

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

`.env` не включается в Git или архив исходников. В текущей рабочей копии создан локальный `.env` со случайным паролем и правами `0600`.

## Что реализовано

- Регистрация, вход/выход, Argon2id, серверные сессии, HttpOnly cookies, CSRF, ограничение запросов через Redis, изоляция данных по пользователю.
- Главный экран, последняя глюкоза (в том числе со вчерашнего дня), IOB с обновлением каждые 30 секунд, углеводы и инсулин за текущий день.
- Дневник с фильтрами и датой: глюкоза, фактический инсулин, еда, активность, дневные сводки, заметки. Удаление с проверкой версии и аудитом.
- «Добавить запись»: все разделы на одной прокручиваемой странице. Пустые разделы пропускаются; заполненные сохраняются атомарно. Калькулятор доступен на той же странице и отдельной кнопкой.
- Фиасп/Fiasp распознаётся как быстрый инсулин аспарт, Тресиба/Tresiba — базальный деглудек. Базальный инсулин исключён из болюсного IOB. Шаг болюсного и базального устройства задаётся отдельно, входит в исторический snapshot.
- AI: настоящий Responses API через OpenAI или Tokenn, личный зашифрованный ключ, согласие на передачу агрегатов выбранному сервису, Structured Outputs, Safety Layer, история объяснений и число использованных токенов. Нет инструментов изменения дозы/терапии.
- Серверный Bolus Engine, отдельные IOB и Safety Layer. ICR / ISF / target / correct_above зависят от времени в часовом поясе аккаунта. Результат и фактическая доза хранятся отдельно. Подтверждение идемпотентно.
- Полные JSON-снимки расчёта, версия алгоритма, архивные версии терапевтического профиля. Исторические расчёты не пересчитываются.
- Поиск еды через YAZIO (USDA — дополнительный fallback), свои продукты, блюда, готовый вес и порции, нутриентные snapshots, недавние продукты, избранное. Поддержаны граммы и миллилитры. Примерный каталог не выдаётся в личных аккаунтах.
- Цикл, история, календарь и приблизительные фазы. Фаза не изменяет коэффициенты инсулина.
- Аналитика 24 ч / 7 / 14 / 30 / 90 дней; среднее, медиана, SD, CV, доли измерений в/ниже/выше диапазона, суточный инсулин и углеводы. Тренировки сопоставляются с измерениями до и после, без причинных выводов.
- PDF A4 с кириллицей, графиками, таблицей терапии и нумерацией; XLSX, CSV UTF-8, полный JSON backup. Очередь Celery и центр загрузок. Скачивание только владельцем.
- Шесть тем, шесть вариантов помощника, отдельная иллюстрация кота, десять шагов настройки и подтверждение параметров. Никаких наказаний за показатели.
- PWA manifest, иконки, service worker, IndexedDB-очередь для глюкозы/инсулина/еды. Повторная синхронизация не создаёт дубликаты. Расчёт болюса офлайн запрещён.
- Удаление аккаунта каскадно удаляет персональные строки и файлы отчётов.

## Apple «Здоровье»

Карточка Apple «Здоровье» на главной или «Профиль → Подключения» принимает экспорт ZIP/XML с iPhone. В «Здоровье»: профиль → «Экспортировать все данные о здоровье» → сохранить в «Файлы» → выбрать архив в Bolus.

Импортируются `Workout` (тип, время, длительность, источник) и `ActivitySummary` (дневная энергия и минуты упражнений). Повторные записи распознаются стабильным идентификатором; дневные суммы не прибавляются к тренировкам. Активность показывается в дневнике, на графике и в аналитике. Записи `Record`, включая сырые шаги с пересекающихся устройств, не суммируются: это исключает недостоверное двойное считывание.

Лимиты MVP: файл до 20 МБ, XML внутри ZIP до 60 МБ, до 10 000 импортируемых записей. Оригинальный файл не сохраняется после обработки. Для больших архивов нужен дальнейший потоковый импорт.

**Прямой доступ HealthKit доступен в iOS-приложении `ios/`.** Оно читает разрешённую активность и после подтверждения сохраняет её в локальный дневник на iPhone, без сервера. Синхронизация запускается вручную. В PWA сохраняется импорт XML/ZIP. Ни веб-версия, ни iOS-приложение не записывают инсулин в «Здоровье».

[Документация Apple по доступу к HealthKit](https://developer.apple.com/documentation/xcode/configuring-healthkit-access).

## Внешние каталоги

**YAZIO заменил FatSecret.** Поиск включён по умолчанию (`YAZIO_ENABLED=true`) и проверен без API-ключа и входа в YAZIO, в том числе при использовании Apple/Google для личного аккаунта YAZIO. Backend обращается только к каталогу продуктов; учётные данные и дневник в YAZIO не отправляются. Поиск начинается с двух букв. Регион и язык: `YAZIO_COUNTRY=RU`, `YAZIO_LOCALE=ru_RU`. При необходимости можно подключить резервный USDA через `USDA_API_KEY`.

Состав нормализуется на 100 г **или 100 мл** по `base_unit`. У жидкостей неизвестная масса не подменяется объёмом; в записи хранятся `amount`, `unit=ml`, `grams=null`. Неуказанные клетчатка и сахар остаются неизвестными. Использовано предоставленное описание YAZIO v15; это не официальный SDK и доступность публичного endpoint может измениться. [Подробности и ограничения](docs/YAZIO.md).

## Медицинская математика и ограничения

Подробно: [docs/ALGORITHMS.md](docs/ALGORITHMS.md).

`bolus-v1.1.0`: еда = carbs / ICR; положительная коррекция только строго выше correct_above; ниже target применяется отрицательная коррекция; IOB вычитается из суммарного положительного результата. Результат ограничивается снизу нулём и округляется **вниз до выбранного шага устройства**. Новая ручка по умолчанию имеет шаг 1 ЕД; доступны 0,5, 0,25 и 0,1 ЕД, для базальной ручки также 2 ЕД. Превышение max_bolus блокирует расчёт до округления. Старые snapshots без шага сохраняют прежнюю политику 0,1 ЕД.

## Подключение AI

В текущей установке ключ шифрования уже создан. Для новой установки создайте `APP_ENCRYPTION_KEY` командой `docker compose run --rm --no-deps backend python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`, сохраните результат в `.env` и перезапустите backend/worker. Сам API-ключ вводится в «Профиль → Подключения → OpenAI / Tokenn». Выберите сервис, выпустивший ключ. Для Tokenn используется `https://api.tokenn.pro/v1`, модель `gpt-5.5`; ключ Tokenn не работает напрямую в OpenAI. Сохраните и нажмите «Проверить подключение»: это реальный короткий запрос без данных дневника. Для анализа дополнительно включите согласие на передачу агрегатов выбранному сервису и сохраните настройки. Без ключа приложение показывает состояние подключения, не выдумывает AI-ответы.

Подробности, границы отправляемых данных и источники: [docs/PERSONAL_UPDATE.md](docs/PERSONAL_UPDATE.md).

По ручным записям показывается **доля измерений**, а не истинное время в диапазоне. Отсутствующие данные не интерполируются. Средние суточные суммы делятся на все дни периода, включая дни без записей; ноль записей не означает нулевую реальную дозу или питание.

## Проверки

```sh
docker compose exec backend pytest -q --cov=app.bolus --cov=app.iob --cov=app.safety --cov=app.analytics
cd frontend
npm ci
npm run typecheck
npm run build
npm audit --audit-level=high
```

Тесты охватывают 140 статических golden cases (независимый рациональный oracle), Hypothesis, IOB, safety, единицы, часовой пояс, изоляцию аккаунтов, CSRF, каскадное удаление, идемпотентность подтверждения, версии профиля, импорт Apple Health, форматы отчётов и разделение AI/дозы. CI выполняет также `pip-audit`.

Приложение для iPhone: `cd ios && swift test` проверяет ядро (golden cases и общие с Python векторы bolus / IOB / аналитики / арифметики), `xcodebuild test -scheme Bolus` — сценарии SwiftData на симуляторе. GitHub Actions `.github/workflows/bolus-local-first.yml` в корне репозитория запускает Python-эталон, проверку воспроизводимости векторов, `swift test` на Linux и macOS, сборку приложения, тесты на симуляторе и Release-сборку для устройства.

[Результаты проверок](docs/VERIFICATION.md) и [статус ТЗ / план версий](docs/STATUS.md).

## PWA и HTTPS

В localhost можно проверить service worker. Для установки на настоящий iPhone необходим собственный доступный HTTPS-адрес с доверенным сертификатом; `localhost` на iPhone относится к самому телефону, не к Mac. Шаблон TLS-конфигурации находится в `nginx/https.conf.example`. При развёртывании: `ENVIRONMENT=production`, `SECURE_COOKIES=true`, точный `ALLOWED_ORIGIN`, `DEMO_ENABLED=false`. Приложение отказывается запускаться в production с небезопасными cookies.

Секреты в production должны поступать из secret manager; `.env` с правами файла не является шифрованием секретов. Обязательны шифрование дисков/резервных копий, ограничение инфраструктурного доступа и отдельный security review. Этот репозиторий автоматически не создаёт домен, сертификаты или облачный хостинг.

## Разработка без Docker

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cd backend
../.venv/bin/alembic upgrade head
../.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8001
# В другом терминале из корня:
cd frontend
npm ci
npm run dev
```

SQLite и синхронный Celery-режим используются только для локальной разработки; в Compose всегда PostgreSQL, Redis и отдельный worker.

## Структура

`ios/` — local-first приложение для iPhone: `Sources/BolusCore` (детерминированное ядро, паритет с Python), `Bolus/` (SwiftData, HealthKit, SwiftUI), тесты и генератор Xcode-проекта.
`frontend/` — Next.js, React, TypeScript, Tailwind CSS, Radix Dialog, Recharts.
`backend/app/` — API, модели, схемы, repositories, bolus, iob, safety, analytics, food, cycle, reports, imports, AI integration и personalization contracts.
`backend/alembic/` — версионируемые миграции.
`worker/`, `nginx/`, `docs/` — инфраструктура и документация.

## Хранение и очистка

Личные записи хранятся до удаления пользователем. Файлы отчётов доступны 7 дней; демо-аккаунты и истёкшие сессии очищаются явной maintenance-командой. Команда без `--apply` ничего не удаляет:

```sh
docker compose exec backend python -m app.services.maintenance
# Применить выбранную retention policy:
docker compose exec backend python -m app.services.maintenance --apply
```

Для рабочего развёртывания администратор должен настроить запуск этой команды по расписанию и retention резервных копий. Удаление из активной БД не удаляет данные из внешних инфраструктурных backups; их жизненный цикл управляется отдельно.
