# Bolus local-first для iPhone

Обновление 4 октября 2026. iOS-приложение `ios/` больше не является оболочкой над сервером. Это нативное SwiftUI-приложение: дневник, профиль терапии, расчёт болюса, IOB, цикл, аналитика, Apple «Здоровье», продукты, отчёты и резервные копии работают на iPhone без сервера и без интернета.

Для работы приложения **не нужны** Docker, FastAPI, Next.js, PostgreSQL, Redis, Nginx, домашний сервер, VPS и адрес сервера. Регистрации, входа, cookies и CSRF в приложении нет.

Python backend сохранён как эталонная реализация (reference) для проверки паритета и для прежней веб-версии. Runtime-зависимостью iOS-приложения он не является.

## Архитектура

```
SwiftUI (ios/Bolus/UI)
   │  читает/пишет только через
   ▼
DiaryStore (@Observable, @MainActor) ── SwiftData (локальная база на iPhone)
   │  вызывает
   ▼
BolusCore (ios/Sources/BolusCore) — детерминированное ядро без UI, БД и сети
   BolusEngine bolus-v1.1.0 · SafetyLayer · IOBEngine linear-remaining-v1.0.0
   CycleEngine · сегменты профиля · аналитика · продукты · отчёты · backup

Сервисы iOS: HealthKit (HealthReader) · Keychain · LocalAuthentication
             NWPathMonitor (только подсказка о сети) · URLSession (только YAZIO/USDA и AI)
```

- `BolusCore` компилируется прямо в target приложения и отдельно как Swift-пакет для тестов (`swift test`). Ядро не импортирует SwiftUI, SwiftData, HealthKit и не делает сетевых запросов; транспорт для каталогов еды и AI передаётся снаружи и используется только этими функциями.
- Математика Python воспроизведена побитово: `Decimal` (28 знаков, ROUND_HALF_EVEN, `Decimal(str(float))`), `round()`, `statistics.mean/median/pstdev`, `sum()` Python 3.12 и арифметика `datetime/timedelta` с микросекундами.
- `DiaryStore` — единственное место записи в базу: валидация и расчёты берутся из ядра, магазин только сохраняет и публикует изменения.

## Локальная база (SwiftData)

| Модель | Содержимое |
|---|---|
| `DiaryEntry` | `id`, `clientID`, `kind` (glucose, insulin, meal, activity, activity_summary, note), `occurredAt`, `data` (JSON в формате backend), `createdAt`, `updatedAt`, `version`, `dedupeKey` (UUID HealthKit, подтверждение расчёта) |
| `TherapyProfile` | версия, `validFrom`/`validTo`, статус, тип терапии, названия инсулинов, `bolusIncrement`, `basalIncrement`, `maxBolus`, DIA, сегменты времени с ICR/ISF/target/correctAbove, подтверждение. Новая версия архивирует прежнюю; архив не редактируется |
| `BolusCalculation` | `calculatedAt`, неизменяемые `inputSnapshot` и `calculationSnapshot`, `actualBolus`, `confirmedEntryID`, `algorithmVersion` |
| `Food` | свои продукты, сохранённые продукты YAZIO/USDA, рецепты (ингредиенты, готовый вес, порции), избранное, `lastUsedAt`. В записи еды хранится снимок нутриентов, поэтому изменение продукта не меняет историю |
| `Cycle` | `startDate`, `endDate`, `cycleLength`, `actualOvulationDate` |
| `AIInsight` | вопрос, проверенный ответ, отправленный контекст, провайдер, модель, токены |
| `AuditEvent` | локальный журнал изменений |
| `AppSettings` | настройки (имя, единицы, часовой пояс, тема, питомец, блокировка). Секретов здесь нет |

Схема версионирована (`BolusSchemaV1`, `BolusMigrationPlan`), поэтому следующие изменения моделей получат явные миграции.

## Что работает без интернета

| Функция | Airplane Mode | Комментарий |
|---|---|---|
| Запуск, дневник, история, фильтры | ✅ | данные только на устройстве |
| Глюкоза, инсулин, еда, активность, заметки, цикл | ✅ | одна форма «Добавить запись», атомарное сохранение |
| Расчёт болюса, Safety Layer, подтверждение фактической дозы | ✅ | профиль, IOB и движок локальные; AI не участвует |
| IOB | ✅ | только подтверждённые быстрые дозы, DIA из записи введения |
| Цикл и фазы | ✅ | фаза не меняет дозу |
| Аналитика и графики (Swift Charts) | ✅ | отсутствие данных — «нет данных», а не 0 |
| Apple «Здоровье» → дневник | ✅ | HealthKit читается на устройстве |
| Свои продукты, рецепты, избранное, недавние | ✅ | |
| Отчёты PDF, CSV, XLSX, JSON | ✅ | генерируются на iPhone, затем системное меню «Поделиться» |
| Экспорт и восстановление резервной копии | ✅ | |
| Face ID / Touch ID / код-пароль | ✅ | |
| Поиск YAZIO / USDA | ❌ нужен интернет | экран еды не блокируется: показываются локальные продукты и понятное сообщение |
| AI-анализ (OpenAI / Tokenn) | ❌ нужен интернет и ключ | дневник и расчёт продолжают работать |

Модули ядра и `DiaryStore` не проверяют сеть: отказ сети не может помешать открыть дневник или выполнить детерминированный расчёт.

## Паритет с Python

| Набор | Где | Объём |
|---|---|---|
| Golden cases | `backend/tests/golden/bolus_cases.json` = `ios/Tests/BolusCoreTests/Fixtures/golden_bolus_cases.json` (побайтовое совпадение проверяется pytest) | 120 |
| Bolus vectors | `bolus_vectors.json` | 2362 |
| IOB vectors | `iob_vectors.json` | 613 |
| Analytics vectors | `analytics_vectors.json` | 80 периодов |
| Числовые векторы | `numeric_vectors.json`: `round`, `statistics`, `sum`, смешанный `int/float` `sum` | 1150 |

Векторы генерирует `backend/scripts/generate_shared_vectors.py` из Python-эталона; их проверяют и pytest (`tests/test_shared_vectors.py`), и XCTest (`SharedVectorTests.swift`). CI заново генерирует векторы и падает, если они изменились.

Эталонная версия Python — **3.12**, как в `backend/Dockerfile`. С 3.12 `sum()` для float использует компенсированное суммирование, поэтому несколько округлённых сумм отличаются от 3.11. Генератор отказывается работать на Python < 3.12; ядро повторяет поведение 3.12, включая смешанные суммы `int` и `float` (`duration_minutes` — `int` у ручных тренировок и `float` у Apple Health).

Осознанное отличие: суточные инсулин, углеводы, калории и коррекции в Swift равны `nil`, если за период нет таких записей; Python возвращает `0`. Это требование «не интерпретировать отсутствие данных как 0». Во всех остальных случаях результаты совпадают побитово.

## Резервная копия

- «Настройки → Экспортировать все данные» создаёт JSON с `format: "bolus-local-backup"` и `schemaVersion: 2`: профили, записи, расчёты, продукты, циклы, история AI, журнал и настройки. API-ключи в копию не попадают.
- «Восстановить из резервной копии» сначала показывает план: сколько записей новых, сколько совпадает и сколько конфликтует. Добавляются только новые записи; при совпадении `id` с другим содержимым остаётся версия устройства. Настройки восстанавливаются только на пустом устройстве. Ничего не перезаписывается молча.
- Миграции формата выполняет `BackupMigrator`: копия версии 1 (JSON-экспорт прежнего сервера Bolus) преобразуется в версию 2. Копия новее приложения отклоняется с понятным сообщением.

### Перенос данных с сервера на iPhone

1. В прежней веб-версии создайте отчёт формата **JSON** (полная резервная копия) и сохраните файл.
2. Передайте файл на iPhone (AirDrop, «Файлы», почта).
3. В Bolus на первом экране нажмите «Перенести данные из резервной копии» или откройте «Настройки → Восстановить из резервной копии».
4. Проверьте план и подтвердите. Профили, записи, расчёты, продукты, циклы и история AI появятся в локальной базе. После этого сервер можно выключить.

Этот путь проверяет тест `DiaryStoreTests.testServerBackupMigratesIntoTheLocalStore` на настоящем JSON-экспорте сервера: настройки, обе версии профиля, записи, продукты, цикл и история AI переносятся один раз; подтверждённый на сервере расчёт остаётся подтверждённым без второй записи инсулина; последующая синхронизация HealthKit узнаёт перенесённую тренировку по UUID; повторный импорт ничего не добавляет.

## Готовность к iCloud / CloudKit

CloudKit в первой версии отключён (`cloudKitDatabase: .none`), но модели подготовлены: у всех атрибутов есть значения по умолчанию, нет уникальных ограничений и обязательных связей, идентификаторы — UUID, дедупликация выполняется в `DiaryStore` по `id`/`dedupeKey`. Для включения нужны iCloud capability с контейнером, `cloudKitDatabase: .private(...)` и правила разрешения конфликтов для одновременных правок на нескольких устройствах.

## Безопасность и приватность

- Ключи OpenAI/Tokenn и USDA хранятся только в Keychain (`WhenUnlockedThisDeviceOnly`), не в UserDefaults, SwiftData, исходном коде или резервной копии.
- AI получает только агрегаты периода и, по выбору, снимок выполненного расчёта; имя, заметки и вся база не отправляются. Ответ проверяется Safety Layer: AI не возвращает исполняемую дозу и не может изменить ICR/ISF/DIA.
- Внешние запросы идут через эфемерный `URLSession` без cookies, кэша и перенаправлений.
- HealthKit — только чтение: тренировки, шаги, активная энергия, минуты упражнений, дистанция. Повторная синхронизация обновляет записи по UUID тренировки и дате сводки и не создаёт копий.
- Блокировка приложения необязательна: Face ID / Touch ID с запасным код-паролем; в переключателе приложений содержимое скрыто.

## Критерий готовности (раздел 17 ТЗ)

| Шаг | Автоматическая проверка | На физическом iPhone |
|---|---|---|
| Установка | Release-сборка для `generic/platform=iOS` без подписи в CI | нужна ваша Apple Team (см. `ios/README.md`) |
| Wi-Fi и сотовые данные выключены, перезапуск | ядро и `DiaryStore` не обращаются к сети | проверить вручную |
| Глюкоза, еда, расчёт болюса, фактическая доза, IOB | `DiaryStoreTests.testOfflineDiaryBolusAndPersistenceAcrossRestart` на симуляторе | проверить вручную |
| Закрыть, перезапустить, данные сохранились | тот же тест открывает базу заново по тому же пути | проверить вручную |
| Импорт HealthKit | `testHealthSyncDoesNotDuplicate` (без дублей) | разрешения и реальные данные — только на устройстве |
| Аналитика | 80 векторов паритета с Python | проверить вручную |
| PDF / CSV / JSON (и XLSX) | `testReportsAreGeneratedLocally` | открыть Share Sheet |
| С интернетом: поиск еды и OpenAI | контракты YAZIO/USDA/AI в тестах ядра | проверить с сетью и своим ключом |

Сборка и тесты на симуляторе выполняются в GitHub Actions (`.github/workflows/bolus-local-first.yml`). Проверка на физическом iPhone требует устройства и подписи и в этой поставке не выполнялась.

## Ограничения

- Синхронизация между устройствами (CloudKit) не включена; перенос — через резервную копию.
- HealthKit синхронизируется вручную; фоновая доставка и перенос удалений из «Здоровья» не реализованы.
- Сканер штрихкодов не реализован.
- PDF строится нативно (UIGraphicsPDFRenderer) по содержанию прежнего отчёта для врача; вёрстка отличается от серверной.
