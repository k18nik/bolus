# Личный режим, AI и шаг устройства

Обновление 3 октября 2026. Владелец указал личное использование и сообщил о проведённой клинической валидации. На этом основании локальная настройка расчёта включена. Содержимое клинических материалов разработчик не проверял; этот файл фиксирует изменение продукта и технические проверки.

## Добавление записей

Одна прокручиваемая форма содержит глюкозу, еду, фактический быстрый/базальный инсулин, активность, цикл, заметку и калькулятор. Все разделы необязательны. `POST /diary/batch` валидирует заполненные разделы и сохраняет их одной транзакцией. Повторный client_id с тем же содержимым возвращает прежний результат; с другим содержимым — 409. Ошибка одного раздела откатывает весь запрос. Офлайн ставятся в очередь пакеты только из глюкозы, еды и инсулина. Незаписанный фактический инсулин нужно сохранить перед расчётом IOB.

## Инсулин и шаг

Фиасп/Fiasp распознаётся как быстрый инсулин аспарт, Тресиба/Tresiba — как базальный инсулин деглудек. Названия сохраняются в записях, snapshots и AI-контексте; несоответствие известного названия выбранному типу отклоняется. Подстановка фиксированной DIA по названию не выполняется: используется подтверждённая DIA профиля. Тресиба не входит в болюсный IOB. Название не заменяет самостоятельную модель фармакодинамики.

Источники классификации: [инструкция Fiasp производителя](https://www.novo-pi.com/fiasp.pdf), [инструкция Tresiba производителя](https://www.novo-pi.com/tresiba.pdf). Шаг выбирается по конкретному устройству, а не только названию инсулина.

Параметры `bolus_increment` и `basal_increment` задаются отдельно. При шаге 1 ЕД результат 3,5 округляется вниз до 3; при шаге 0,5 остаётся 3,5; при шаге 0,25 результат 3,75 сохраняется. `bolus-v1.1.0` показывает исходную сумму и результат округления. Фактическая доза проверяется на кратность шагу из snapshot расчёта. Изменение профиля не меняет старый расчёт. Legacy snapshots без поля используют 0,1 ЕД. Исторические данные не переписываются.

## OpenAI и Tokenn

Используется [Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), REST через server-side httpx. Поддержаны два явно выбираемых провайдера: OpenAI (`https://api.openai.com/v1`) и Tokenn (`https://api.tokenn.pro/v1`). Произвольные адреса и HTTP redirects запрещены. По умолчанию для OpenAI используется `gpt-4.1-mini`, для Tokenn — `gpt-5.5`; модель можно изменить на доступную ключу. API-ключ хранится в `ai_settings.encrypted_key` с Fernet; мастер-ключ — только backend environment `APP_ENCRYPTION_KEY`. Ключ не возвращается API, не хранится в localStorage, не включается в аудит или JSON backup. Сохраняйте мастер-ключ для восстановления encrypted credentials.

Внешняя отправка происходит при нажатии «Отправить в OpenAI» / «Отправить в Tokenn», после явного согласия для выбранного сервиса: вопрос пользователя, агрегаты периода, почасовые средние, общие сведения о терапии/активности/фазе, а при выбранном болюсе — его числовой snapshot. Имя, email, свободные заметки и полная база не отправляются. Вопрос сам по себе может содержать введённые пользователем личные данные. Запрос использует `store:false`; это не утверждение об отсутствии всех журналов провайдера или его поставщиков моделей. При смене провайдера UI снимает согласие и требует его ключ заново.

«Проверить подключение» выполняет короткий реальный запрос к выбранной модели без медицинских данных, даже если согласие на анализ дневника ещё не выдано. Он использует токены. Успешная проверка сохраняется до изменения ключа/модели/провайдера. Ключ Tokenn не является ключом OpenAI: прямой запрос в OpenAI возвращал 401, а запрос в Tokenn с тем же ключом прошёл. Для совместимости с Tokenn JSON-схема также явно включается в инструкцию модели; фактический ответ всё равно строго валидируется на сервере.

Модель возвращает только объяснения по схеме `InsightResponse`. Ответы проходят `app/safety/ai_output.py`; новые дозировки, запрещённые поля и tool calls отклоняются. У AI нет методов изменения профиля, расчёта, введения инсулина. Лексический фильтр текста — дополнительная проверка, не доказательство клинической корректности каждого объяснения.

История содержит провайдера, модель, дату, входные/выходные/общие токены. Ошибки ключа, лимита, соединения, отказа модели и неполного JSON показываются явно. Ответа-заглушки нет. Реальный запрос требует вашего ключа и доступного API-баланса. Расход считается по usage API; технические проверки и неудачные запросы могут тарифицироваться провайдером и не входят в счётчик сохранённых анализов. Последняя проверка показывает свой расход отдельно.

## Демо

`DEMO_ENABLED=false`. UI не создаёт demo sessions, старые demo sessions не допускаются в личный режим. Существующие синтетические записи не преобразуются в реальные и не копируются в личный аккаунт. Тестовые fixtures остаются только для автоматических проверок. В личном поиске еды нет примерного seed-каталога: доступны свои продукты и подключённые внешние источники.
