# Каталог YAZIO

Источник контракта: предоставленный владельцем `yazio_public_api-master.zip`, `swagger.json` и `examples/search_products.js`. Описание сообщества: https://github.com/saganos/yazio_public_api. Лицензия описания сохранена в `THIRD_PARTY_YAZIO_LICENSE.txt`. Это не официальный SDK YAZIO. Код примеров не запускается, встроенные в примеры OAuth client credentials не используются.

## Подключение

`YazioProvider` реализует существующий `FoodProvider` и заменяет FatSecret. Используется только `GET https://yzapi.yazio.com/v15/products/search`. Внешний адрес фиксирован, redirects запрещены, timeout ограничен. Backend передаёт текст поиска, страну и язык каталога. Публичный поиск проверен 3 октября 2026: HTTP 200 без Authorization, cookies и аккаунта. Способ входа пользователя в YAZIO через Apple/Google не влияет на этот поиск. Чтение личного дневника, аккаунта или публикация продуктов в YAZIO не реализованы.

По фактическому ответу API поле `sex` обязательно, хотя Swagger помечает его необязательным. Для совместимости передаётся фиксированное `YAZIO_SEARCH_SEX=male` из примера архива. Это техническая настройка каталога, не пол пользователя и не атрибут медицинского профиля. Она не участвует в математике болюса. Допустимы `male` / `female`. `YAZIO_COUNTRY=RU` и `YAZIO_LOCALE=ru_RU` можно изменить для другой базы. [YAZIO описывает влияние страны базы на поиск](https://help.yazio.com/hc/en-us/articles/11804332619665-How-does-the-food-product-search-work-within-Yazio).

Не требуются пароль YAZIO, пароль Apple/Google, access token или API-ключ. Если сервис перестанет разрешать публичный поиск, приложение показывает причину, сохраняет доступ к собственным продуктам и при настроенном `USDA_API_KEY` пробует резервную базу. Автоматических попыток получить аккаунт или обойти отказ авторизации нет.

## Нутриенты и единицы

Состав ответа относится к одной базовой единице. Для `base_unit=g` значения умножаются на 100 и показываются на 100 г; для `base_unit=ml` — на 100 мл. Поля `amount` и `serving_quantity` внешнего ответа описывают типичную порцию и не используются как знаменатель нутриентов.

Проверенные реальные результаты:

| Продукт | База | Углеводы | Энергия |
|---|---|---|---|
| Макароны, приготовленные | 100 г | 30,86 г | 158 ккал |
| Кола, Coca Cola | 100 мл | 10,58 г | 41 ккал |

Следовательно, 180 г этих макарон дают 55,548 г углеводов; 250 мл этой колы — 26,45 г. Эти значения относятся к указанным карточкам на дату проверки, не заменяют состав конкретной упаковки.

Обязательны конечные неотрицательные углеводы, белки, жиры и энергия. Неизвестные единицы, NaN/Infinity, отрицательные, отсутствующие или недопустимые значения приводят к пропуску продукта и видимому уведомлению. Нулевые углеводы принимаются только как явно указанное число. Отсутствующие клетчатка/сахар сохраняются как `null`; карточка показывает «Не указано». В рецепте их сумма неизвестна, если хотя бы один ингредиент не содержит значения.

В API поле `serving_weight` сохранено ради совместимости как размер базовой порции; его единица задаётся `base_unit`, а не обязательно граммами. У новых жидких MealItem сохраняется объём `amount`, `unit=ml`, `grams=null`: плотность не выдумывается. Рецепт рассчитывает нутриенты из введённых количеств и отдельно указанной массы готового блюда. Недавние продукты и избранное сохраняют правильную единицу. Старые записи и расчёты не изменяются при обновлении каталога.

## Границы

- Запрос к внешнему каталогу только от двух символов; до 30 валидных результатов, с удалением повторных ID.
- Пустой результат и сбой API различаются в интерфейсе. Собственные продукты доступны при сбое.
- Endpoint штрихкодов не описан в архиве; камера и barcode-поиск не добавлялись этим обновлением.
- Автоматические тесты используют MockTransport, живые контрольные запросы выполняются отдельно. Публичный контракт может измениться без предупреждения.
