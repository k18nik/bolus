# Проверки сборки

Проверено 3 октября 2026 на macOS (локальная разработка) и в Docker Desktop (Linux containers).

- **116 tests passed** в backend pytest.
- 140 сохранённых golden cases с ожидаемыми результатами, полученными независимой рациональной арифметикой без вызова production engine.
- Hypothesis: 350 комбинаций bolus inputs, 100 комбинаций шага устройства и углеводов, отдельно монотонность/границы IOB.
- Statement coverage модулей `bolus`, `iob`, `safety`, `analytics`: **100%** (113 statements в текущей реализации). Это покрытие кода тестами, не оценка клинической полноты.
- Изоляция аккаунтов, CSRF, строгие схемы, mg/dL, snapshot нутриентов, архивные профили, подтверждение расчёта, каскадное удаление.
- Шаги 0,1 / 0,25 / 0,5 / 1 ЕД, округление вниз, неизменяемый шаг в snapshot, валидация фактической дозы; Фиасп/Тресиба, исключение базального из IOB.
- Пакетное сохранение необязательных полей, атомарность, повторные запросы без дублей, конфликт client_id, последняя глюкоза при одинаковом времени измерений.
- OpenAI / Tokenn Responses API через HTTP MockTransport: выбор правильного адреса, контракт Structured Outputs, агрегированный контекст, шифрование/удаление ключа, согласие, изоляция аккаунтов, токены, ошибки провайдера и некорректные ответы, блокировка дозировок и tool calls. AI не изменяет профиль, расчёт или фактический инсулин.
- Apple Health: XML и ZIP, UTC normalization, запрет XML entities, повторный импорт, отсутствие двойных записей.
- Нативный HealthKit sync: повторный UUID, обновление дневной сводки, частичные разрешения без выдуманных нулей, чужой ожидаемый аккаунт, будущие даты и атомарный откат; IOB и терапия не изменяются.
- YAZIO: точный публичный HTTP-контракт без авторизации, пересчёт с одной базовой единицы, порция не влияет на знаменатель, g/ml, неизвестные fiber/sugar, некорректный состав и единицы, пустой поиск, недоступность API и видимые сообщения, USDA fallback, избранное/недавние/рецепты, неизменяемые snapshots.
- Экспорт: PDF signature, XLSX чтение через openpyxl, UTF-8 BOM и ISO 8601 в CSV, JSON schema_version и отсутствие password_hash, совпадение summary с analytics, mg/dL, флаги питания/цикла, неправильные периоды.
- Next.js: TypeScript check и production build проходят.
- npm audit: 0 известных vulnerabilities на момент проверки.
- pip-audit: no known vulnerabilities на момент проверки.

## Реальная инфраструктура

`docker compose up -d --build` успешно поднял frontend, backend, PostgreSQL, Redis, Celery worker и Nginx. Проверены healthchecks и HTTP через http://localhost:8080.

После замены каталога реальные запросы через развёрнутый API `/api/foods/search` вернули по 30 продуктов YAZIO для «макароны» и «Coca Cola», без предупреждений. Прямой публичный endpoint YAZIO также проверен без токенов: HTTP 200, русские наименования, разные базовые единицы г/мл. Nginx теперь повторно разрешает адреса контейнеров через Docker DNS: устранён воспроизведённый 502 после смены IP frontend при пересборке. `nginx -t` и загрузка приложения прошли.

Отдельный HTTP smoke-test на настоящем PostgreSQL/Redis:

- /health, frontend, последняя глюкоза, аналитика за 24 часа, миграция избранного — OK.
- Два конкурентных подтверждения одного расчёта возвращают один и тот же InsulinEntry; фактическая доза не дублируется.
- Все четыре формата сгенерированы **асинхронным Celery worker** и скачаны через Nginx: PDF, XLSX, ZIP/CSV, JSON.
- Доступные файлы создаются в общем volume backend/worker.

Реальное подключение Tokenn проверено 3 октября: `GET /v1/models` — 200, доступна `gpt-5.5`; `POST /v1/responses` — успешный структурированный ответ. Последняя проверка через production-код использовала 624 токена, отдельный запрос ассистенту с пустым контекстом — 1323 токена; схема и Safety Layer пройдены. Данные дневника не передавались, тестовый ответ не добавлялся в пользовательскую историю. Сохранённый ключ привязан к Tokenn; согласие на передачу медицинских агрегатов новому провайдеру оставлено выключенным. Ошибка прежней конфигурации воспроизведена: ключ Tokenn возвращал `401 invalid_api_key` при прямом обращении к OpenAI.

## Визуальная проверка

Проверен русскоязычный интерфейс в браузере, мобильные размеры 360/390/430 и desktop. Проверяются отсутствие горизонтального скролла, отображение карточек, модальные формы и нижняя навигация. В браузере пройден сценарий глюкозы и еды: 180 г макарон = 55,62 г углеводов, сохранение еды и переход к серверному расчёту. В Docker проверены UI-блокировка устаревшей глюкозы и успешное сохранение фактических 5 ЕД отдельно от рекомендации; IOB изменился на фактическую дозу.

После обновления личного режима на отдельном синтетическом аккаунте проверены:

- отсутствие демо-баннера, демо-входа и подставленных медицинских записей;
- единая прокручиваемая форма открывается сверху, все разделы доступны без переключения;
- сохранение одной глюкозы и отдельное пакетное сохранение глюкозы, еды, Тресибы и заметки;
- inline-калькулятор показывает 3,5 до округления и 3 ЕД при шаге 1; ввод фактических 3,5 отклоняется; 3 ЕД сохраняются как Фиасп, IOB обновляется;
- последняя глюкоза при равном времени берётся из последней сохранённой записи;
- экран подключения OpenAI, незаполненный ключ, явное согласие, модель и счётчик токенов;
- форма и настройки AI не имеют горизонтального переполнения на 360/390/430 px.

Для YAZIO дополнительно проверены живой поиск «Coca Cola» на 390 px, карточка «Кола» с 100 мл и неизвестными клетчаткой/сахаром, сохранение в избранное, выбор избранного в единой форме и успешное сохранение 250 мл с 26,45 г углеводов. На 360 и 430 px ширина контента равна ширине экрана. Проверка выполнена в отдельном временном аккаунте, не в личном дневнике владельца.

Синтетический аккаунт проверки удалён после теста. Локальный профиль владельца получил новую версию с шагом 1 ЕД; прежние параметры терапии и исторические расчёты сохранены. Все шесть Docker-сервисов работают, миграция `0004_ai_provider` применена.

Восьмистраничный PDF отчёта для врача отрендерен через Poppler и визуально просмотрен: кириллица, A4, поля, таблицы, графики и номера страниц читаемы, наложений не обнаружено. В production-пакет включён DejaVuSans с лицензией.

## iOS local-first (4 октября 2026)

Проверено в GitHub Actions (`.github/workflows/bolus-local-first.yml`, Xcode на `macos-latest`, симулятор iPhone Air, iOS 26.5):

- **BolusCore, 84 теста** на Linux (Swift 6) и macOS: 120 golden cases, 2362 bolus-, 613 IOB-, 80 аналитических и 1150 числовых векторов совпадают с Python побитово; Safety Layer, профили, цикл, продукты, AI-контракты, отчёты CSV/XLSX/PDF-содержимое, резервные копии и миграция серверной копии, устойчивость к некорректным данным.
- **Python-эталон**: 121 тест backend; векторы заново генерируются из Python 3.12 и совпадают с сохранёнными.
- **Сборка приложения** Debug для симулятора и Release для `generic/platform=iOS` без подписи; компилятор не выдал предупреждений.
- **Тесты SwiftData на симуляторе** (`BolusAppTests`): глюкоза → еда → расчёт → фактическая доза → IOB → повторное открытие базы с сохранёнными данными; заблокированный расчёт сохраняется, но не подтверждается; версии профиля не переписываются; HealthKit без дублей; резервная копия туда и обратно без дублей при повторе; удаление записей и всех данных; PDF/CSV/XLSX/JSON на устройстве; перенос JSON-экспорта прежнего сервера.

Не проверено: установка на физический iPhone с подписью, Airplane Mode на устройстве, разрешения и реальные данные HealthKit, Face ID, системное меню «Поделиться», живые запросы YAZIO/USDA/OpenAI с телефона.
